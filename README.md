# fhedsoma

**fhedsoma** is a C++17 implementation of the CKKS homomorphic encryption scheme with Python
bindings, built for one job: **summing encrypted model states in Federated
Learning (FL)**.

- Backend: NTT-based polynomial multiplication, Montgomery reduction, `#pragma omp simd`.
- Python modules (import names unchanged): `ckks_python` (pybind11 extension) and `ckks_federated` (high-level, Flower-ready).
- Supported homomorphic operation: `Ciphertext + Ciphertext`. Nothing else is exposed to Python.

## Purpose

In FL, each client trains locally and sends its **model state** (the weights, not an update
or delta) to a server. With additive HE the server can aggregate those states without seeing them:

1. Every client scales its state by `|D_i|/1024` (`|D_i|` = size of its local dataset) and
   encrypts the result with the shared public key.
2. The server adds the ciphertexts. It holds no secret key.
3. A client decrypts the sum and **normalises after decryption** (divides by `Σ|D_i|/1024`),
   which gives the weighted FedAvg state.

The `1024` is a public `2^10` factor: it cancels in the normalisation and keeps the weighted sum
1024 times smaller than `Σ|D_i|·w`, so it stays below `q/(2Δ)`.

The library is specialised for this flow, so it leaves out what FL does not
need: ciphertext × ciphertext multiplication, rotations, relinearization,
key-switching, bootstrapping, and modulus chains. It also exposes raw
polynomial access (`Poly`, zero-copy NumPy views) for research on custom FL protocols.

## How it works

- **Ring:** `Z_q[X]/(X^N+1)`, `N` a power of two, `q` a prime with `q ≡ 1 (mod 2N)`
  (generated by `generate_prime(bits, N)`, `q < 2^62`).
- **Encoding:** canonical embedding. A real vector of up to `N/2` values becomes an
  integer polynomial scaled by `Δ = 2^scale_bits`.
- **Keys:** ternary secret key `s`; public key `(pk0, pk1) = (-a·s + e, a)`.
- **Encryption:** `c0 = pk0·u + e0 + m`, `c1 = pk1·u + e1`, with fresh `u` (ternary)
  and `e0, e1` (discrete Gaussian, σ = 3.2). Two NTT multiplications per encryption.
- **Aggregation:** coefficient-wise `mod_add` of `c0` and `c1`.
- **Decryption:** `m' = c0 + c1·s`, then decode.
- **Auto-chunking (`CKKSTensor`):** arrays longer than `N/2` are split into several
  ciphertexts and reassembled on decryption.

### Limits you must know

| Limit | Consequence |
|---|---|
| Additive only | The server cannot rescale. Clients apply the `|D_i|/1024` weight in plaintext before encrypting; the normalisation by `Σ|D_i|/1024` happens after decryption. |
| Single modulus, no rescaling | Zero multiplicative depth. |
| Overflow budget | Each *coefficient* of the summed plaintext polynomial must stay below `q/2`. With `Δ=2^40` and a 52-bit prime that is about `q/(2Δ) = 2048` unscaled additions. The summed polynomial carries `Σ(|D_i|/1024)·w`, so the budget is `Σ(|D_i|/1024)·max|w| < q/(2Δ)` (bounding by `max|w|` is the safe choice, since the mean never exceeds it). |
| `CKKSTensor.decrypt()` returns real parts only | Use `Encoder.decode()` for complex slots. |
| Built with `-march=native` | The `.so` is not portable across CPU architectures. Rebuild per machine. |
| No standard parameter enforcement | You choose `(N, bits)`. `N=4096, bits=52` is the minimum recommended for 128-bit security. `N=1024` is for experiments only. |
| Secret key handling | Never send `sk` to the server. Use `ctx.make_public()` or `CKKSContext.load(path, public_only=True)` there. |

## Project structure

```
CMakeLists.txt        builds static lib `ckks_core` (+ Python module with CKKS_BUILD_PYTHON=ON)
setup.py              pip install of ckks_python + ckks_federated
include/              C++ headers: math_utils, poly, ntt, sampler, encoder, keygen,
                      encryptor, decryptor, evaluator, ckks_ops, ckks_types
src/                  C++ sources (ntt, sampler, keygen, serialization, evaluator, ...)
bindings/module.cpp   pybind11 bindings for every public type
ckks_federated/       high-level Python layer: CKKSContext, CKKSTensor
tests/cpp/            CTest unit tests per module
tests/                FL stress tests, overflow reproduction, precision test, noise diagnostic
test_py_*.py          end-to-end Python tests
USING_CKKS_FEDERATED.md   integration guide for other projects
CLAUDE.md             full API reference and implementation status
docs/                 LaTeX write-ups (ckks_para_fl, dissertacao_baixo_nivel)
```

Modules: (1) Math/NTT, (2) Sampling, (3) CKKS core, (4) FL ops, (5) Python API,
(6) Serialization, (7) `ckks_federated`. Scalar multiplication is not started.

## Installation

Requires a C++17 compiler (GCC 9+/Clang 10+), CMake 3.18+, Python 3.8+, `numpy`, `pybind11`.

**pip (consumer projects):**

```bash
pip3 install .
```

**CMake (development):**

```bash
mkdir build && cd build
cmake .. -DCKKS_BUILD_PYTHON=ON \
         -Dpybind11_DIR=$(python3 -c "import pybind11; print(pybind11.get_cmake_dir())")
make -j$(nproc)
```

Without installing, `sys.path.insert(0, "build"); import ckks_python`.

## Usage

### High level (`ckks_federated`)

```python
import numpy as np
from ckks_federated import CKKSContext, CKKSTensor

K = 10                                    # number of clients
sizes = np.array([800, 1200, 1024, 500, 2000, 900, 1100, 1500, 700, 1300])   # |D_i|
weights = sizes / 1024                    # per-client scale |D_i|/1024

# Key holder (client side)
ctx = CKKSContext(N=4096, bits=52, scale_bits=40)
ctx.save("keys/")                         # params.pkl, pk.bin, sk.bin

# Each client: scale its model state by |D_i|/1024, then encrypt
states = [np.random.randn(10_000) for _ in range(K)]
payloads = [CKKSTensor(ctx, w * s).serialize() for w, s in zip(weights, states)]   # list[bytes] for gRPC

# Server: public key only, adds ciphertexts, cannot decrypt
server_ctx = CKKSContext.load("keys/", public_only=True)
agg = CKKSTensor(server_ctx, payloads[0])
for p in payloads[1:]:
    agg += CKKSTensor(server_ctx, p)

# Client: decrypt, then normalise by Σ|D_i|/1024
result = CKKSTensor(ctx, agg.serialize()).decrypt() / weights.sum()
assert np.allclose(result, np.average(states, axis=0, weights=sizes), atol=1e-4)
```

`CKKSContext` supports `pickle` (multiprocessing, Flower) and `from_keys(...)`
to rebuild a context from key bytes received over the network.

### Low level (`ckks_python`)

```python
import numpy as np, ckks_python

N, q, scale = 1024, 4503599627366401, 2**40   # q ≡ 1 (mod 2N)
sk = (kg := ckks_python.KeyGenerator(N, q)).gen_secret_key()
pk = kg.gen_public_key(sk)

enc  = ckks_python.Encoder(N, q, scale)
ct   = ckks_python.Encryptor(N, q, pk).encrypt(
           ckks_python.Plaintext(enc.encode(np.array([1.5, -2.0]))))
ev   = ckks_python.Evaluator(N, q)
ct2  = ev.add(ct, ct)
pt   = ckks_python.Decryptor(N, q, sk).decrypt(ct2)
out  = enc.decode(ckks_python.Poly(N, q, pt.poly))   # ≈ [3.0, -4.0, 0, ...]
```

See `USING_CKKS_FEDERATED.md` for the integration guide and `CLAUDE.md` for the full API.

## Experimental results

Measured on this machine (Linux, Python 3.10, `-march=native`) by running the commands above.
All 17 CTest suites pass (14 C++, 3 Python). Errors are the maximum absolute error per slot against the plaintext result.

| Experiment | Setup | Max error |
|---|---|---|
| FedAvg, C++ (`test_fl_aggregation`) | 90 clients, Δ=2^40, each input pre-scaled by 1/90 (test setup) | real 4.6e-09, imag 3.0e-09 |
| FedAvg, C++ (`test_stress_aggregation`) | N=1024, 200 clients, 512 slots | real 1.6e-07, imag 1.4e-07 |
| FedAvg, C++ (`test_stress_aggregation`) | N=4096, 100 clients, 2048 slots | real 4.4e-07, imag 6.2e-07 |
| FedAvg, Python (`test_stress_federated`) | N=1024, 100 clients, 2567 values (6 chunks) | 1.2e-07 |
| Chunk round trip, serialize, save/load | N=1024, 2567 values | 1.1e-08 to 1.3e-08 |
| Blind server (`make_public`) | server aggregates, client decrypts | 2.0e-08; server `decrypt()` raises `PermissionError` |
| 10 additions (`test_precision`) | error per coefficient | 3.9e-12 (243,962× below the 2^-20 tolerance) |

**Overflow boundary, no client-side scaling** (every client adds up to Δ per coefficient):

| Test | Prime | Theoretical limit `q/(2Δ)` | Result |
|---|---|---|---|
| C++, N=64 | `15·2^48+1` | ≈ 1920 | correct up to K=1900 (overflow ratio 0.99), error 1.6e-08 |
| Python, N=1024, 52-bit prime | `4503599627366401` | 2048 | correct up to K=3000 (error 5.6e-07) |

The Python sweep stays correct beyond the theoretical K because the limit applies to
polynomial **coefficients**, not slots. The encoder uses the canonical embedding, so
`|a_k| ≤ (2/N)·Σ|z_j|`: zero-mean data and single large slots are diluted by `N/2`.

**Overflow reproduced on purpose** (`tests/test_overflow_federated.py`, N=1024, 52-bit prime,
Δ=2^40, limit `q/(2Δ) = 2048`, wrap error `q/Δ = 4096`). A vector with a high **mean** is the
worst case: a constant `v` encodes to the constant polynomial `v·Δ`, so coefficient 0 grows as `K·v·Δ`.

| Case | Result |
|---|---|
| Constant 1.0, K=1843 (0.9× limit) | correct, error 5.6e-07 |
| Constant 1.0, K=2252 (1.1× limit) | **wrong by exactly 4096.000 (= q/Δ) in every slot** |
| Zero-mean random, K=2252 | correct, error 5.5e-07 |
| One slot = 1.0, K=2252 | correct, error 4.3e-07 |
| Constant 1.0, K=2252, each input scaled by `1/K` | correct, error 4.8e-07 |
| Mean sweep at K=1000, `K·mean/limit` = 0.50 / 0.95 | correct, errors 3.6e-07 / 2.9e-07 |
| Mean sweep at K=1000, `K·mean/limit` = 1.05 / 2.00 | **wrong by 4096** |

Failure starts exactly where `K·mean` crosses `q/(2Δ)`, and the error is a whole multiple of `q/Δ`
(after any later rescaling, e.g. dividing by a total weight, it becomes a large constant offset in
every slot of the affected packet). The limit applies to the **server-side sum** and to coefficients,
not to single client inputs or single slots. Fix: keep `Σ(|D_i|/1024)·max|w|` below `q/(2Δ)`, i.e. shrink the client-side scale factor, lower `Δ`, or raise `q`.
